The Guacamayo Loop

Five nodes, one cycle. Every session generates telemetry; hooks enforce guardrails and record events; the metacognition skills derive patterns and propose changes; the retro graduates hypotheses into permanent config; improved config shapes the next session.

The loop map — two planes, one cycle

There are more loops than the five-node diagram above suggests. The workflow plane (top) is where work happens: triage feeds execute, execute feeds review, and both triage and review log decisions. The metacognition plane (bottom) runs in parallel — it consumes the session data those loops produce, updates insights, renders this dashboard, and raises retros that propose config changes. Each node names the skills that actually fire.

Triage loop — scoping through refinement; evaluates and logs decisions that manage the state board
Execute — the center; re-entered from review, skipped on bug/ and spike/
Review loop — dimension agents emit findings; recurring signatures get promoted back into the dimensions
Metacognition — consumes session data from both loops → insights → dashboard → retro → config

The triage loop's decision log has no reader that measures effect, and the review loop's promotion step is manual. Those are the two open gaps — see Loop Health for the stage-by-stage view.

The pipeline is not linear

Drawn as research → plan → refine → execute → review, but that is the artifact order, not the traversal. In practice stages repeat, skip, and reverse — and each traversal is a session, which is why pipeline behaviour shows up in Session Health rather than as its own tab.

review → executefindings send work back; the same issue re-enters execute without a new plan
plan → researchrefine gates on DoR; a plan that fails it drops back to research
skip to executebug/ and spike/ branches carry no plan doc at all
one issue, many sessionsa task checklist splits execute across sessions on one branch — the phase boundary is the session boundary

Only 37% of plan docs carry an issue reference, so stage transitions are joinable on roughly a third of the corpus. Re-entry counts are therefore a floor, not a total.

Context Health

Is context under control? Are sessions staying lean?

The 150k cliff: Sessions that grow past 150k context tokens cost 5× more per turn because the overflow can't be cached. In early July, 66-75% of sessions were hitting this cliff. The goal is <30%. Compaction is the mechanism — it compresses prior conversation to reclaim context space. Autocompact was broken Jul 15-18 (zero auto-triggered compactions despite sessions reaching 300k–557k tokens) and fired reliably every day since Jul 19 in the transcripts examined — but Ramsey reports it not firing in terminal mode (Jul 30 and again Jul 31). The Jul 30 investigation that found "no defect" read a VS Code session, so it never covered that surface. Treat this claim as contested pending a terminal-mode transcript.
