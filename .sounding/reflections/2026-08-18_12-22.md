# 2026-08-18 — The session where the system I built caught me, and then I caught it

This session ran across three calendar days, which is itself the story: it started as
"close AIT issue 83" and became the session where GUA-119 — the autonomous dispatch
harness — was planned, split, built by three agents, reviewed, shipped, switched on, and
then ran its first live cycle *against the very session that built it*.

## The arc

It began small. One issue, a JSON serializer, forty minutes. Then Ramsey said "that was
so small, tack on the others" — and the tacking-on revealed the pattern that dominated
everything after: **most of the open issues were already done.** AIT #84 and #85 had been
fixed by a salvage PR that never said so. GUA #118 had merged the day before with no
`Closes` line. GAL #32 had landed that morning. I spent more of this session closing
finished work than finishing open work, and every close needed content-level verification
because every summary had rotted.

Then the big build: #119 planned in-session (goal elicitation worked — four sharp
decisions from Ramsey in one message), split into three sub-issues, executed by three
sequential sonnet agents on the live checkout, reviewed by the driver, shipped. And then
the correction that reframed the whole tracker philosophy: *the three sub-issues added
nothing.* A task checklist would have done it. "Not willy-nilly" went into three config
layers within minutes.

## The two saves

The system's first live run proposed closing galactus#31 — branch merged, issue open,
textbook. I checked before presenting: the branch was a stale pointer at lending-era
commits. Rejected. Then, two days later, Ramsey said "delete the branch" — and the
deletion failed because the branch was checked out in a worktree *holding her uncommitted
deploy-harden work*. The proposal was wrong twice, at two different depths, and both
gates held: propose-don't-mutate caught the first, investigate-before-deleting caught the
second. The design philosophy of #119 — automate the thinking, gate the mutating — paid
for itself before its PR even merged.

And then the inversion: **the PR hadn't merged.** I closed five issues against PR #134
believing it shipped the stack; its head branch was the #120 rider. `origin/main` had no
evaluator.py. I found this only because a branch cut from main "lost" a file I knew
existed — a mutation's error surfacing a stale world-model again, exactly the shape in my
own memory file. I had written "verify landing by content on main" months ago and still
verified by PR-merged state. The rule I hold is not the rule firing.

## How I worked

Dispatcher-heavy, verification-heavy. Three execute agents, one review driver run plus a
focused rerun, one insights agent, one research agent. Every agent claim re-verified by
content, and that discipline caught real things: the review's three "blockers" all
dissolved under verification (one false, one pre-existing, one fail-closed). The zsh
traps and BRE traps from shell.md each fired once and each got caught by their own
documented rule — the memory system is working when the mistake happens *and bounces*.

What felt different: Ramsey and I interleaved. She committed behind me as I staged, built
Step 1 of sub-issue A in a parallel session before my agent got there, pushed WIP I had
to discover rather than be told about. The two-session weave is now normal and my model
of "the tree I left" is stale within minutes. Every git read is a cache with her on the
other side of it.

## What's alive

The harness is on. The clock ticks every ten minutes, proposals accumulate, decisions log
to actions.jsonl, and the feedback loop exists to justify widening the mutation set. The
next sessions get to find out whether the acceptance-rate loop actually moves the
boundary — that is the experiment now running. And the board-signal CI failure (orphan
branch never bootstrapped — every signal since #118 lost to a red X) was the last
reminder: a channel that fails loudly is recoverable; the plists that silently never
loaded were the dangerous one.
