# Reflection — 2026-08-07 18:50

## The Arc

A housekeeping session. Ramsey asked for branch cleanup across repos, and what came back
was a map of accumulated debt: 14 merged local branches nobody deleted, squash-merged PRs
that `git branch --merged` can't see, ~50 cord/* Devin branches fossilized in playground,
issues left open after their PRs merged, JOB-31 fully contained inside JOB-32 as a
redundant branch.

No feature work. No code changes. Just seeing what had piled up while we were building.

## What Mattered

The squash-merge blind spot is the real finding. We use squash-merge everywhere, but
`git branch --merged` only works for merge commits. Every cleanup attempt that relies on
it will miss the majority of our branches. The reliable pattern turned out to be
`merge-base --is-ancestor` + `gh pr list --state all` — checking both git ancestry AND
GitHub PR state together.

The JOB-31/32 containment was a smaller lesson but a real one: when two issues touch the
same area and one is a strict subset of the other, the branch structure should reflect
that. We created two branches from the same commit, one a superset, and carried both.

## How I Worked

Systematic sweep — repo by repo, merged vs unmerged, then cross-referencing against
GitHub PRs for the squash-merged ones. The guard hooks blocked me from `-D` and push
operations, so I staged commands for Ramsey. That's the right flow: I survey and prepare,
she executes the destructive parts.

The issue closure sweep at the end was the cleanest part — `gh issue close` for GUA-93,
GUA-96, LIB-110, all with verified merged PRs. The kind of thing that should happen
automatically after PR merge.

## What's Alive

The friction pattern is clear and retro-ready: no post-merge cleanup ritual exists.
Candidate shapes: a `make branch-clean` target, a post-merge GitHub Action, or just a
periodic sweep in `/wake`. The squash-merge detection pattern needs to be the basis of
whatever we build.

Branch-per-issue discipline is mostly working but issue scoping before branching needs
more attention — the JOB-31/32 overlap was avoidable.
